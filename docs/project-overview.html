수집

2시간마다 scripts/collect-news.ts가 돌고, 받아온 기사는 그날의 data/news/YYYY-MM-DD.json(KST 기준 날짜)에 병합됩니다.

  1. 16개 피드를 동시에 요청 타임아웃 15초. 실패한 피드는 로그만 남기고 건너뜁니다 — 한 곳이 죽어도 나머지는 그대로 수집됩니다.
  2. 출처 이름 정리 직접 지정한 피드는 source 값을 그대로 쓰고, Google News는 제목이 헤드라인 - 매체명 형태라 뒤쪽을 잘라 매체명으로 씁니다.
  3. 중복 제거 기사 링크의 SHA-1 앞 16자가 id. 같은 기사가 여러 피드에 걸려도 한 번만 저장됩니다.
  4. 분야당 80건으로 자르기 발행 시각 최신순으로 정렬한 뒤 상한을 넘는 오래된 기사를 버립니다. 하루 파일이 무한히 커지지 않게 하는 장치입니다.
  5. 저장소에 커밋 · 푸시 이 커밋이 다시 Vercel 재배포를 일으킵니다. 데이터 갱신과 배포가 한 줄로 이어집니다.

형태소 분석기 없이, 최근 2일치 제목의 단어 빈도만 셉니다. 문자·숫자만 남기고 공백으로 자른 뒤, 2글자 미만과 불용어(속보, 단독, 오늘, 위해, 했다 …)를 버립니다.

두 번째 제목에 삼성전자가 두 번 나오지만 점수는 1점입니다. 한 제목 안에서는 같은 단어를 한 번만 세기 때문에, 한 기사가 혼자서 순위를 밀어 올리지 못합니다. 2건 미만으로 등장한 단어는 아예 버려집니다.

형태소를 나누지 않으므로 정부가와 정부는은 서로 다른 단어로 셉니다. 여러 헤드라인에 반복되는 고유명사를 띄우기엔 충분하지만 정밀한 토픽 추출은 아닙니다. 가장 값싼 개선은 불용어 목록을 늘리거나 조사 제거 규칙을 넣는 것입니다.

Discord 브리핑

하루가 끝날 무렵 그날 수집분을 읽어 급상승 키워드 embed 1개와 분야별 embed 10개를 만들고, 웹훅으로 Discord 매일뉴스브리핑 채널에 올립니다. 각 분야 embed에는 최신 기사 제목 3건이 링크와 함께 들어갑니다.

AI 요약은 현재 꺼져 있습니다. 스크립트에 TODO: AI 카테고리 요약 재도입 주석이 남아 있고, 워크플로우도 ANTHROPIC_API_KEY를 job에 넘기지 않습니다. 지금 나가는 것은 요약이 아니라 제목 목록입니다.

embed 10개 제한 Discord는 메시지 하나에 embed를 10개까지만 받습니다. 분야가 10개가 되면서 키워드까지 11개가 되어, 브리핑은 10개씩 끊어 여러 메시지로 나갑니다. 분야를 더 늘려도 뒤쪽이 조용히 잘리지 않습니다.

배포와 저장

웹은 Vercel, 수집과 전송은 GitHub Actions, 데이터는 저장소 자체입니다. 운영 중인 서버가 한 대도 없고 데이터베이스도 없습니다. 대신 저장소가 하루치 JSON만큼 계속 커집니다 — 분야 10개 × 최대 80건 기준으로 하루 1MB 안팎이라 당분간은 신경 쓰지 않아도 됩니다.

웹 페이지는 최근 2일치를 분야별로 보여주고, 검색 · 즐겨찾기(브라우저에만 저장) · 급상승 키워드를 함께 제공합니다. 서버 컴포넌트가 JSON을 직접 읽고 revalidate = 3600으로 한 시간마다 갱신됩니다.
